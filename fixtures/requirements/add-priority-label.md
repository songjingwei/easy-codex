# 为任务列表增加优先级

## 背景

`fixtures/target-app` 里的 **Task List** 页面已经支持添加任务、勾选完成，并把任务保存在浏览器 `localStorage`（键名 `target-app.tasks`）。

## 目标

在现有任务列表上为每条任务增加 **优先级**，不改变整体页面结构（仍是一个列表 + 添加表单）。

## 范围

- 在 `Task List` 主界面的每一条任务上展示优先级。
- 新建任务时默认优先级为 **中**。
- 用户可以为任务选择 **高 / 中 / 低** 三档之一。
- 列表上方提供按优先级 **筛选**（例如：全部 / 高 / 中 / 低）。
- 继续使用 `localStorage` 持久化；扩展任务数据结构即可。

## 不在范围

- 不新增独立详情页或路由。
- 不接入后端或账号体系。
- 不重构整个应用框架。

## 业务规则

1. 优先级仅允许 `high`、`medium`、`low` 三值；展示文案可为「高」「中」「低」。
2. 缺少优先级字段的历史数据，读取时视为 **中**。
3. 筛选为客户端行为，不请求网络。

## 验收标准

1. 用户能在页面上看到每条任务的优先级，并能修改优先级。
2. 筛选后列表只显示所选优先级的任务（「全部」显示所有任务）。
3. 刷新页面后优先级与筛选相关数据仍正确（依赖现有存储机制）。
4. `fixtures/target-app` 内 `pnpm test` 仍全部通过；为优先级与筛选补充或更新测试。
