# Easy Codex

面向真实 Git 仓库的 **完备 coding agent**，让多个需求在独立 worktree 中并行完成讨论、设计、实现、审查与可核查验收。

Easy Codex 的核心是一套用阶段闸门约束的 **Agent 运行时与开发流程**，绑定仓库后在项目内读取、修改、运行和验证代码。你负责明确目标、确认需求与体验设计；Agent 推进实现并留下审查与验收证据。主界面的游戏化场景是 **参与与进度表达方式**，不是产品本体。

> 项目目前处于产品规划阶段，以下为计划支持的能力。

## 多个需求，同时推进

一个需求正在开发，另一个正在确认设计，第三个还在讨论——你可以随时切换，查看各自的进展和需要你参与的事项。

每个需求都有独立的讨论记录、进度和交付成果。某个需求等待反馈时，其他没有依赖的需求仍可继续推进。

## 从想法到交付

1. **说清需求**：提交需求文档，与 Agent 讨论目标和细节，确认它准确理解了你的想法。
2. **了解影响**：通过围绕现有功能的问答，确认你了解这次改动会影响什么。
3. **先体验，再开发**：实际操作可交互的设计稿，提出修改意见，满意后再进入开发。
4. **持续推进实现**：Agent 整理开发计划并完成实现，你可以跟踪每个需求的进展。
5. **查看验收结果**：交付前完成审查和实际验证，并提供图片、视频或验收记录，方便你核查结果。

## 基于你的项目，延续已有体验

Easy Codex 从项目已有的功能和页面出发理解需求，让新增功能与现有产品的风格和使用习惯保持一致。

需求共识、设计稿、实现成果和验收记录会随需求保留，方便回顾每次改动的目标与结果。

## 部署形态

桌面应用与服务端部署是同一套 Agent 与工作台的两种宿主，差异主要在执行环境、凭据与隔离策略，业务流程与阶段规则保持一致。

接入自己的项目后，即可围绕多个需求与 Agent 协作。

更完整的产品定义、流程与阶段见 [项目目标](docs/PROJECT_GOALS.md)，前端、两种部署形态与 Agent 的实现选型见 [技术栈](docs/TECH_STACK.md)。
